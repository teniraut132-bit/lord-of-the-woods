# Хозяин леса — общий мир · версия 3.5

Приложение использует **Supabase как единственный источник рабочего состояния**. Состояние государств, регионов, молитв, благословений, контрактов, друидов, общего журнала, армий и истории боёв загружается из общей базы и синхронизируется между браузерами.

## Что хранится где

- `lotw_shared_data`: единое состояние игрового мира и военного советника, с ревизиями для защиты от незаметной перезаписи.
- `lotw_profiles`: персональное имя игрока и выбранное государство.
- `lotw_activity`: общая очередь действий и обращений, ответы владельца.
- `lotw_admins`: роли администратора и владельца.

В браузере остаётся только резервный снимок последнего загруженного/сохранённого облачного состояния и Auth-сессия Supabase. Игровые данные при обычной работе **не читаются из локальной базы и не сохраняются туда как рабочая копия**. Кнопка экспорта формирует JSON-резервную копию облачного мира; импорт явно загружает выбранную копию обратно в общий мир.

## Перенос старых локальных данных

При первом запуске новой версии браузер, в котором осталась база версии 3.4 или старше, предложит одноразово добавить локальные государства и записи журнала в общую базу. Уже существующие облачные государства не заменяются; совпадающие ID и названия пропускаются. Локальная исходная копия не удаляется. Кампания военного советника переносится отдельно, только когда общая кампания ещё пуста.

Если у другого игрока тоже осталась своя старая локальная база, он должен открыть новую версию в том же браузере и подтвердить добавление найденных данных. Данные, которые никогда не открывались в новой версии, можно передать через экспорт/импорт резервной копии.

## Подключение

1. В Supabase включить **Authentication → Sign In / Providers → Anonymous Sign-Ins**.
2. Оставить включённым Email provider для входа владельца в административный режим.
3. В `backend-config.js` должны быть Project URL и публичный publishable key. Секретный/service_role ключ в браузер не помещать.
4. Итоговая схема находится в `supabase/schema.sql`. В проекте владельца она уже развёрнута миграциями; повторно запускать SQL в рабочей базе не нужно.
5. Публикация GitHub Pages выполняется автоматически при коммите в `main`.

Без Anonymous Sign-Ins игрок не сможет получить постоянный идентификатор браузера и подключиться к общей базе. При этой ошибке приложение показывает, что общий мир не загружен, и не переключается на локальную базу.

## Синхронизация и параллельные изменения

Общий мир проверяется примерно раз в 12 секунд, а очередь администратора — примерно раз в 15 секунд. Запись выполняется с проверкой ожидаемой ревизии. Если два участника одновременно изменили одну и ту же общую часть, второе сохранение останавливается с предупреждением; нужно обновить страницу и повторить действие, чтобы не затереть изменения другого участника.

## Резервные копии

- ⇩ — скачать полную резервную копию текущего общего мира, включая кампанию военного советника.
- ⇧ — явно восстановить выбранную резервную копию в общий мир.
- Локальный резервный снимок используется только для возможности скачать последнюю копию, если облако временно недоступно; он не загружается автоматически как игровое состояние.

## Важное замечание о доступе

В текущем общем режиме любой пользователь, успешно прошедший Supabase Auth (включая анонимную сессию), может редактировать общее состояние мира. Это подходит только для доверенной игровой группы. Перед открытым публичным запуском нужно добавить распределение прав на уровне отдельных государств/армий, чтобы участник мог менять только свои данные, а владелец — весь мир.
