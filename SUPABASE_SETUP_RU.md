# Хозяин леса — настройка общего мира Supabase

## Уже выполнено в проекте владельца

Для проекта `wlzoiyqpfaseiaoknrlk` уже созданы и защищены таблицы:

- `lotw_shared_data` — общее состояние приложения и военного советника;
- `lotw_profiles` — имя игрока и выбранное государство;
- `lotw_activity` — очередь действий и ответов;
- `lotw_admins` — роли администратора/владельца.

Выполнены миграции с RLS, закрытой функцией проверки роли администратора и RPC `lotw_save_shared_data`, которая сохраняет общие данные по ожидаемой ревизии. Владелец уже назначен в `lotw_admins` с ролью `owner`.

**Не запускайте повторно SQL в существующем рабочем проекте.** Файл `supabase/schema.sql` — итоговый шаблон для новой установки.

## Обязательная настройка Auth

1. Откройте [Authentication → Sign In / Providers](https://supabase.com/dashboard/project/wlzoiyqpfaseiaoknrlk/auth/providers).
2. Найдите **Anonymous Sign-Ins** и включите переключатель.
3. Проверьте, что Email provider включён — он нужен владельцу для входа в административную панель.

Если Anonymous Sign-Ins выключен, в логах появится `anonymous_provider_disabled` / `Anonymous sign-ins are disabled`, и ни одна анонимная сессия игрока не сможет открыть общий мир.

## Конфигурация клиента

В корне репозитория должен находиться `backend-config.js` с Project URL и публичным publishable key. Такой ключ специально предназначен для браузерного клиента. Никогда не помещайте в репозиторий `service_role`, `sb_secret` или пароль владельца.

## Общая модель данных

- Все участники читают общий снимок приложения: государства, регионы, ресурсы, благосклонность, Клирику, контракты, молитвы и журнал.
- Все участники читают/изменяют общую кампанию военного советника: армии A/B, подразделения, осадные орудия, приказы и историю боёв.
- Имя игрока и выбранное государство сохраняются в его собственной строке `lotw_profiles`.
- Действия по-прежнему регистрируются в `lotw_activity`; владелец видит очередь и может отвечать игрокам.
- При обновлении браузер получает свежую общую ревизию примерно каждые 12 секунд; очередь администратора обновляется каждые 15 секунд.
- При одновременных правках проверка ревизии не допускает незаметной перезаписи. Если появляется конфликт, обновите страницу и внесите изменение повторно.

## Перенос старых локальных сохранений

После первого входа новая версия ищет старую локальную базу 3.4 только для одноразового переноса. Если в общей базе уже есть государства, локальные государства будут добавлены без замены совпадающих ID или названий. Журнал объединяется по ID. Военная кампания переносится только в том случае, если общая кампания ещё пуста.

Это не режим локальной работы: после переноса приложение загружает игровое состояние из Supabase. Локально сохраняется только резервный снимок для экспорта.

Если игрок открывает сайт с другого компьютера или браузера, он получает тот же общий мир. Его имя и выбранное государство хранятся в его Auth-профиле.

## Проверка после включения Anonymous Sign-Ins

1. Откройте сайт и обновите страницу через Ctrl+F5.
2. В Supabase → Authentication → Users должна появиться анонимная запись.
3. Измените тестовое государство или добавьте тестовый журнал.
4. Откройте сайт во втором браузере — изменения должны появиться автоматически.
5. Войдите владельцем в «Режим администратора» и проверьте общую очередь.
